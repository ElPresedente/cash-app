# Подключение Google Таблиц

## Что уже подготовлено

Пустая копия исходного шаблона: https://docs.google.com/spreadsheets/d/1TE13iPqQCg-b4eOBLaPrXbQtbjnIV-qV0R8hZt1_VZw/edit

Это эталон для копирования другим пользователям. Создайте личную рабочую копию через **Файл → Создать копию**. Приложение блокирует запись в эталон по его ID.

В приложении откройте **Настройки → Google Таблицы → Как настроить подключение**.

## Один раз настроить Google Cloud

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект «Копилка».
2. Включите [Google Sheets API](https://console.cloud.google.com/apis/library/sheets.googleapis.com).
3. Откройте **Google Auth Platform**. В **Branding** укажите имя приложения и свой email поддержки.
4. В **Audience** выберите **External**, оставьте режим **Testing**, добавьте свой аккаунт в **Test users**.
5. В **Data Access** добавьте `https://www.googleapis.com/auth/spreadsheets`.
6. В **Clients → Create client** выберите **Web application**.
7. В **Authorized JavaScript origins** укажите `http://127.0.0.1:5173`. Если используете localhost, добавьте также `http://localhost:5173`. Это именно origin, без пути и завершающего слэша. Redirect URI для используемой popup token-модели не нужен.
8. Скопируйте **Client ID** вида `…apps.googleusercontent.com` в поле приложения. Client Secret не нужен; не отправляйте его и не добавляйте в код.
9. Вставьте ссылку на **свою рабочую копию**, нажмите **Войти в Google**, разрешите доступ и нажмите **Проверить таблицу**.

Официальные инструкции: [OAuth consent](https://developers.google.com/workspace/guides/configure-oauth-consent), [OAuth Client ID](https://developers.google.com/workspace/guides/create-credentials), [вход по token-модели](https://developers.google.com/identity/oauth2/web/guides/use-token-model).

Для других пользователей: у каждого своя копия таблицы. На этапе Testing добавляйте их аккаунты в Test users. Для распространения за пределами тестирования потребуется настроить production-аудиторию и пройти применимую проверку OAuth у Google. После публикации веб-приложения добавьте его HTTPS origin в настройки OAuth клиента.

## Как работает обмен

- **Загрузить из таблицы** читает счета, категории и операции месячных листов. Предпросмотр и подтверждение обязательны перед заменой локального учёта. Предыдущая локальная версия сохраняется в `kopilka.before-google-import` браузерного хранилища.
- В пустой таблице без счетов приложение предлагает два локальных стартовых счёта; при отправке они будут добавлены в неё.
- **Отправить новые операции** добавляет отсутствующие счета, категории и операции. Строки по ID не дублируются. Перед записью проверяются заголовки, свободные клетки и выпадающие списки. После записи перечитываются ID.
- Запись операций идёт в `Январь…Декабрь!A5:K500`. Общий лист **Операции!A4** вычисляется формулой, приложение туда не пишет.
- Формулы, заголовки, оформление и остальные разделы шаблона сохраняются. Суммы передаются числом в рублях, даты — числом даты Google Sheets, текст — строковыми значениями, без исполнения формул из названий.
- Токен Google живёт только в памяти вкладки, не попадает в localStorage, экспорт или Git. После обновления страницы/истечения доступа нужно войти снова. В хранилище остаются только публичный Client ID и ссылка на таблицу.

## Границы первой версии

Обмен ручной, добавляющий: изменения/удаления уже существующих строк из приложения не переносятся обратно. Несовпадение существующей операции отменяет отправку. Переименованный импортированный счёт и отличающийся начальный остаток тоже требуют сначала актуализировать таблицу и загрузить её снова. Старые категории в таблице не удаляются автоматически.

Поддерживаются рубли и четыре типа приложения: **Расход, Доход, Перевод, Получен займ** (последний соответствует получению кредита в приложении). Операции **Выдан долг, Возврат долга, Возврат займа, Платёж по кредиту** пока не моделируются: если они есть, импорт/отправка отменяются целиком с объяснением. Архивные счета и неактивные категории пока загружаются вместе с остальными для корректной истории. Настройка их статусов из приложения не реализована.

Год берётся из `Настройки!B3`: шаблон рассчитан на один год. Запись доступна в подготовленные строки счетов/категорий 2–100, месячных операций 5–500. Вместе с существующими данными проверяются все 200 строк справочников. Одновременное редактирование разными устройствами пока не поддерживается: проверка свободных строк снижает риск, но Google Sheets не даёт атомарного compare-and-set для такого обмена.

## Что проверено

Сборка, тесты преобразования данных и планирования записей; структура и пустота облачного шаблона; интерфейс подключения. Реальный OAuth-вход и отправка из приложения остаются непроверенными до настройки Client ID пользователем.
