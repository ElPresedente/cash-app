### Подтверждённые требования

1. React + TypeScript, mobile-first приложение «Копилка».
2. Обычное нажатие «+» — серия небольших форм для быстрого заполнения операции.
3. При вводе названия предлагать одну наиболее похожую операцию.
4. Выбор предложения пропускает категорию и ведёт к сумме. Если у операции нет подкатегории, но у категории подкатегории доступны, сначала открыть их селектор.
5. На экране суммы выбирать счёт списания, без селектора бюджетов.
6. Удержание «+» открывает меню: доход, расход, перевод, кредит. Зажатый палец переводится на тип; отпускание открывает большую форму без автоматизации.
7. Полная форма содержит дату, тип и остальные поля; мастер и форма создают одну сущность операции.
8. Навигация приложения, интеграция Google Sheets позднее.
9. Пользователь выбрал локальный репозиторий `O:\zjunk\cash-app`, remote `https://github.com/ElPresedente/cash-app.git`.

### Допущения реализации, которые можно пересмотреть

- Рубли, один пользователь, без авторизации. Данные локально в браузере.
- Нижние вкладки на мобильном: Обзор, Операции, Счета, Настройки; боковая панель на компьютере.
- Базовые категории и подкатегории заданы в коде; редактор категорий отложен.
- Сходство по нормализованному названию и расстоянию редактирования, одно предложение от порога 0.6. Тип операции должен совпадать. Счёт, сумма и дата не переносятся.
- Подкатегорию можно явно пропустить. В полной форме никаких автоподстановок по истории.
- Удержание 420 мс. Есть альтернативы с клавиатуры и в настройках.
- Суммы — целые копейки; не более двух десятичных знаков. Перевод меняет два счёта и не входит в доходы/расходы.
- «Кредит» на первом этапе означает получение заёмных средств. Он увеличивает баланс, но не доход. Графики, проценты, остаток долга и погашения не моделируются.
- Остаток счёта может стать отрицательным. Начальные остатки положительные или нулевые.
- Начало без операций; демоданные только по явной кнопке, с подтверждением замены существующих операций.
- Экспорт JSON готов; импорт и Google Sheets отложены. Повреждённое хранилище не перезаписывается до явной очистки.
- Публикация и отправка изменений на GitHub не выполнены: текущий этап — локальная рабочая версия.

### Проверка первой версии

`npm run build` — успешная производственная сборка и строгая проверка TypeScript.
`npm test` — 5 проверок предметной логики, все прошли.
Установка зависимостей: npm audit сообщил 0 уязвимостей.

Браузерная проверка на мобильной ширине: создание расхода через мастер, подсказка одной похожей операции, обязательное открытие селектора доступных подкатегорий после предложения без подкатегории, открытие меню удержанием «+», открытие полной формы перевода, сохранение перевода и восстановление обеих записей после обновления страницы. Общий баланс при переводе сохранялся. Тестовые операции затем удалены. Жест с удержанием и движением пальца реализован, но на реальном сенсорном устройстве ещё не проверен. Десктопная раскладка проверена сборкой, полноценная визуальная проверка на широком экране ещё впереди.

### Редактирование счетов

По запросу пользователя добавлена кнопка «Редактировать» в каждой карточке на вкладке «Счета». Форма открывается с текущим названием и начальным остатком. Сохранение сохраняет идентификатор и цвет счёта, обновляет только название и начальный остаток. Связанные операции остаются на этом счёте, баланс автоматически пересчитывается. Закрытие формы отменяет несохранённые изменения.

### Удаление счетов

В форме редактирования добавлено удаление с явным подтверждением и отменой. Последний счёт и счета со связанными операциями (в том числе входящими переводами) удалить нельзя. Сначала требуется удалить связанные операции. При удалении свободного счёта его начальный остаток исключается из общего баланса.
